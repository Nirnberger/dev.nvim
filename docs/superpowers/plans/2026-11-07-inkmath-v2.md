# inkmath.nvim v2 Implementation Plan (standalone, interop, speed)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every task is TDD: write the failing tests first, see them fail, implement, see them pass, commit.

**Goal:** Make inkmath usable without `setup()`, fully configurable through one schema, a well-behaved neighbour of other UI plugins (render-markdown, markview, snacks.image, image.nvim), and fast enough that typing never waits for it (md keystroke < 8 ms, tex 5000 keystroke < 5 ms, attach < 10 ms). Also make it easy to extend and maintain.

**Architecture:** Four new small hub modules carry the extension points, so features plug in without growing `core.lua`:
- `config/schema.lua` is one ordered table. It drives the defaults, validation, unknown-key warnings with did-you-mean, per-filetype overrides and the generated options section of `doc/inkmath.txt`.
- `detect/registry.lua` maps filetype to `{lang, detector, ctx}`. A new filetype or detector is one `register()` call.
- `events.lua` fires the `User InkMath*` events. `log.lua` holds the notify levels and a `notify_once` that can be re-armed.
- `api.lua` is the only public surface. `init.lua` re-exports it, and `commands.lua` and the `<Plug>` maps call it.

`enable.lua` owns the policy (guards, disable flags, sticky state). `core.lua` keeps the mechanism (attach/detach/refresh). The conceal handling moves from core to `view/conceal.lua`, and the render queue moves to `render/queue.lua`.

**Tech Stack:** Lua on Neovim 0.12 (floor stays 0.11: guard 0.11.4+ APIs such as async `LanguageTree:parse(range, cb)` with `vim.fn.has`), mini.test (`make test`, `make test-file F=…`), node worker tests (`make test-worker`), `dev/bench.lua` (`make bench`), kitty graphics protocol.

**Spec:** the approved v2 design (Phase 1 standalone and configurable, Phase 2 interop, Phase 3 speed and polish; restated per task below). Evidence and rationale: `docs/research/2026-11-07-usability-audit.md` (cited as *audit §n*) and `docs/research/2026-11-07-speed-and-config-survey.md` (*survey §n*). Baseline numbers: `docs/superpowers/reports/2026-11-07-optimizations.md`.

## Global Constraints

- **Dev isolation:** every nvim run uses `NVIM_APPNAME=inkmath-dev` (the Makefile does this). Never read or write `~/.config/nvim` or the default nvim data dirs.
- **Backward compatibility:** every key in the current `config.lua` keeps its name, type and default: `filetypes, backend, fallback, highlight, scale, inline.{x_height,baseline,promote,promote_ratio}, display.center, preview.{enabled,debounce_ms}, debounce_ms, max_images, workers, cell_size, macros, conceal.{level,cursor}, vimtex.math_conceal`. `require("inkmath").setup(opts)` and `:InkMath enable|disable|toggle|refresh|clear-cache|build` keep working. Existing tests pass unchanged, except the one documented helper change in Task 4.
- **Errors never raise into editing.** Callbacks stay wrapped in `guard`. Config errors from `setup()` come out as one readable `vim.notify` ERROR that lists every bad key, not a traceback, and the previous valid config stays in effect. Unknown keys are WARN, not errors.
- **No default keymaps.** Only `<Plug>` maps and `:InkMath`.
- **`core.lua` must not grow.** `wc -l lua/inkmath/core.lua` must be ≤ 843 after every task and ≤ 700 after Task 12. New behaviour goes into the hub modules.
- **No new module-level `require` in `plugin/inkmath.lua`.** Loading the plugin must stay under 1 ms. All requires happen lazily inside callbacks.
- **Highlights:** user-facing groups (`InkMathError`, `InkMathPreviewBorder`, `InkMathPreviewError`) use `default = true`. `InkMathImg<id>` stays `default = false`, because it encodes the image id.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Config compatibility and merge semantics.** Old configs validate unchanged. A second `setup()` extends the first. Precedence is `vim.g.inkmath` < `setup()` < `overrides[ft]`. A failed `setup()` leaves the old config active. (Task 1)
2. **The OptionSet heuristic** must not treat a `conceallevel` written by render-markdown, markview or our own code as the user hiding images, and with `conceal = false` it must never write window options. (Task 9)
3. **Attach guards and sticky disable:** LSP hover, cmp docs and prompt buffers never attach. A disabled buffer stays disabled across `:e!`, `:set ft=` and `setup()`. An explicit `:InkMath enable` still works on a scratch buffer. (Task 4)
4. **Incremental detection equivalence:** for every edit in the property test, viewport-bounded or precheck-skipped detection must give the same nodes in the scanned rows as a full detect. Stale off-screen rows must never be placed before they are re-detected. (Task 11)
5. **Kitty id namespace:** ids stay inside `[base, base+span)`, are reused after eviction, and never exceed `0xFFFFFF`. `VimLeavePre` deletes only our ids. (Task 8)

### Task 1: Config schema (defaults, validation, unknown keys, merge, overrides)

The other tasks depend on this one, and they add their keys as schema entries. Audit §1 "Validation quality" and "setup() required? Twice? Live?". Survey §3 "enabled as boolean or function".

**Files:** create `lua/inkmath/config/schema.lua`, `tests/test_schema.lua`. Modify `lua/inkmath/config.lua`, `tests/test_config.lua` (add cases only).

**Interfaces:**
- Produces `schema.options`, an ordered list of `inkmath.Opt`:
  ```lua
  ---@class inkmath.Opt
  ---@field path string            -- dotted: "inline.x_height"
  ---@field default any            -- deep-copied; nil allowed (cell_size)
  ---@field check string|fun(v:any):boolean  -- type name or predicate
  ---@field expect? string         -- message for predicate failures
  ---@field doc string             -- one-line doc used by gendoc
  ---@field scope? "global"|"buffer"  -- "buffer" = allowed in overrides (default "global")
  ---@field free? boolean          -- table with arbitrary keys (macros, overrides)
  ---@field nil_ok? boolean
  ```
  Containers (`inline`, `display`, `conceal`, …) are implied by the dotted paths. `conceal` gets an entry with `check = function(v) return v == false or type(v) == "table" end`. Its children are only checked when it is a table.
- `schema.defaults() -> table`
- `schema.validate(tbl, opts?: {where?: string, scope?: "buffer"}) -> errors: string[], warnings: string[]`. The `scope = "buffer"` form rejects global-only keys inside `overrides`.
- `schema.suggest(name: string, candidates: string[]) -> string|nil`. Edit distance ≤ 2, or a unique prefix.
- `config.setup(opts?: table) -> boolean`. Merges onto the accumulated user opts, so a second call extends the first. On error it notifies once (all errors in one message), keeps the old config and returns false.
- `config.get(buf?: integer) -> table`. Read-only resolved config. With `buf`, `overrides[vim.bo[buf].filetype]` is deep-merged on top. Cached per `(generation, ft)`.
- `config.generation: integer`, bumped on every successful `setup`.
- `config.reset()` (tests).
- `config.user() -> table`: the merged user opts, for `:InkMath status` and health.
- Config keys added: `overrides = {}` (free, global; each value is validated with scope "buffer").
- `vim.g.inkmath` (table) is the base layer, read on the first `get()`/`setup()`.

### Task 4: Enable policy: guards, disable flags, sticky disable, live re-apply

Audit top-10 #2 and #3, §4 "Large buffers/non-file buffers". Survey §3 "Disable switches".

**Files:** create `lua/inkmath/enable.lua`, `tests/test_enable.lua`. Modify `core.lua` (attach skips floating-only windows, `set_win_opts` skips floats), `commands.lua`, `tests/helpers.lua`.

**Interfaces:**
- `enable.allowed(buf: integer, opts?: { force?: boolean }) -> boolean, reason?: string`. In order, it checks:
  1. `vim.g.inkmath_disable`
  2. `vim.b[buf].inkmath_disable`
  3. `sticky[buf]`
  4. ft registered and in `filetypes`
  5. `config.get(buf).enabled`: boolean, or `fun(buf): boolean` (pcall; an error counts as false and is logged once)
  6. `buftype == ""` (skipped by `force`)
  7. buffer bytes (`nvim_buf_get_offset(buf, line_count)`) ≤ `max_file_size * 2^20` (skipped by `force`)
  8. not shown only in floating windows (skipped by `force`)
- `enable.set_sticky(buf, disabled: boolean)`. It is cleared on `BufWipeout`, and `:e!` and `:set ft=` keep it.
- `enable.global(on?: boolean) -> boolean`. Sets or reads `vim.g.inkmath_disable`.
- Used by `api._auto(buf)` (the FileType path: `allowed` without force, then `core.attach`) and by `api._reapply()`. After `setup()`, `_reapply` detaches buffers no longer allowed, refreshes attached ones (with `bump`, so the new conceal and scale apply) and attaches newly allowed loaded buffers.
- Config keys:
  - `enabled = true` (`boolean|function`, buffer scope)
  - `max_file_size = 2.0` (MB, number > 0, global)
- Commands:
  - `:InkMath enable|disable|toggle` acts on the current buffer. `enable` uses `force = true`, and `disable` sets sticky.
  - `:InkMath! enable|disable|toggle` acts globally.
- `core.attach(buf)` stays mechanism-only: no policy, so the existing tests and explicit `force` keep working.
- **Helper change:** `tests/helpers.lua` `M.buf` sets `vim.bo[b].buftype = ""` (with `bufhidden = "wipe"`, `swapfile = false`). Without that, scratch test buffers would hit the auto-path guard. This is the only change to existing test code.
