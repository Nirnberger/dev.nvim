## A. Phase 2 review fixes (563d265)

Each fix has a regression test.

- **#1/#2/#12 health interop.** New `interop.lua` holds one table for render-markdown, markview and snacks.image: `loaded`, `latex_on`, `manages(buf)`. I checked it against shallow upstream clones (render-markdown 8e87953, markview aadb6d8, snacks 882c996). Each probe comment cites the upstream file. The probes read only `package.loaded` and `rawget`, so asking never loads a module.
  - **render-markdown:** reads `render-markdown.state`.config.latex.enabled. If state is not loaded, the result is "make sure latex is off".
  - **markview:** loaded means `markview.spec` or `markview` is loaded, so it is found without `setup()`. `latex` is external config: if `spec.config.latex` or its `enable` is missing, the default (on) applies. `spec.get` is not called because it would load markview.config.latex.
  - **snacks:** uses `rawget(Snacks, "image").config` once loaded, or the user's `Snacks.config.image` before that. It counts as on only when `enabled` is set and doc/math are not false.
  - **Fix snippets:** these are now plugin-spec opts, e.g. "`image = { math = { enabled = false } } in your snacks.nvim opts`". The doc and README show lazy.nvim specs.
  - **Tests:** fake modules that mirror the upstream layout. A metatable-backed fake `Snacks` checks that `__index` is never hit. Further tests cover: markview without setup, nothing loaded, and no "setup(" in any snippet.
- **#10:** the `conceal = false` hint checks the filetypes shared with render-markdown/markview through the new `config.for_ft(ft)`, so overrides count.
- **#3 sticky conceal rule.** A `'conceallevel'` 0 counts as the user's only when all of these hold:
  - (a) It is written while a typed key is being handled. A `vim.on_key` flag is cleared by a `vim.schedule` queued with the key, so that schedule runs before any callback the key queued. A typed `:setlocal`/`:set` or a mapping (including a Lua toggle) therefore counts. Writes from `vim.schedule` or timers never count. That covers render-markdown's `Decorator:schedule` -> `Updater:run`.
  - (b) No render-markdown or markview is attached to the buffer (`interop.managers(buf)`). Those plugins write it synchronously from commands too, e.g. `:RenderMarkdown disable`. In such buffers the user uses `:InkMath toggle`.
  - (c) The earlier checks still apply: setlocal/set only, the focused window, and no nested ModeChanged/BufWinEnter/WinEnter/FileType handler.
  - **Doc:** the rule is in `doc/inkmath.txt` under `*inkmath-conceal-sticky*`.
  - **Tests:**
    - render-markdown's exact write path: `vim.schedule` + `{scope="local", win=w}` after a key.
    - a write from a timer.
    - a write from code that was not typed.
    - a typed `:setlocal`.
    - a typed `<F7>` Lua toggle.
    - buffers managed by render-markdown or markview.
- **#4:** `conceal.recheck(buf)` runs from `api._auto` when FileType fires for an attached buffer. A non-nested ftplugin that sets `conceallevel` 0 fires no OptionSet; this now catches it.
- **#5:** Attach is emitted before the first refresh. The test makes every render a cache hit.
- **#7:** `images.evict` remembers the caller's in-use set. `alloc` never steals an id from that set. When nothing is free, `ensure` returns nil, and placer, preview and api skip or error softly instead of stealing.
- **#8:** a failed transmit keeps the id as the oldest resident (`failed[id]`, tick 0). Eviction therefore frees it, it never leaks, it is not freed while on screen, and `ensure` retries the transmit. This deviates from the review's "unmap and free". That fix could hand the id of a placeholder still on screen to another image.
- **#9:** the `api.render` cb is wrapped once in `log.guard("render cb")`, so the sync and async paths behave the same.
- **#6:** the `image_ids.per_instance` doc gives the collision odds (1/224, about 12% for 8 panes) and the fix (`per_instance = false` and distinct `base`). Health prints the id range.
- **#11:** `term/idspace.lua` is the one source of MAX/INSTANCES for the schema and images. **#13:** the doc says where the quarto/rmd treesitter mapping comes from.

## Decisions (ambiguities)

1. **Markdown precheck scope:** the plan says to scan only the edited rows. I scan the edited rows' whole paragraph, bounded by blank lines and capped at 300 rows. Removing `# ` or filling a blank line joins paragraphs, and their `$` re-pair without touching any known node (regression test "joining paragraphs is not skipped"). The cost is a skip ratio of 0 on the bench's md document. Those keystrokes take the parse-free path, so they are still 2.6 ms.
2. **Async parse start:** the tex async parse is started from `vim.schedule`, not inside the keystroke refresh. Starting it inside put its first 3 ms slice into the keystroke (4.7 ms vs 1.6 ms). With `vim.g._ts_force_sync_parsing` it stays synchronous; the tests use that.
3. **Markdown with highlighter:** markdown with the highlighter active often has a valid tree right after an edit. The highlighter's conceal_lines handler parses that row synchronously when `'conceallevel'` > 0. In that case inkmath parses only the injections of the wanted rows. "pending" happens only when the tree really is invalid; it has a 200 ms fallback timer.
4. **Bounded first detection** (beyond the plan): with `want`, the first detection after attach covers only the scanned rows, and the rest is stale for the fill. Without it, the deferred first refresh blocked 34 ms on tex 5000; with it, 10 ms. A tree with errors still gets a full detect. `api.get_formulas` (no `want`) re-detects stale rows.
5. **Re-paired `$$` chains:** an unstable expansion with `want` (a re-paired `$$` chains block after block) stops after 32 rounds. Its wanted rows are kept as correct, and the other rows become stale.
6. **Fill design:**
   - Each fill step is `core.refresh(buf, {lo, hi})`: the chunk is scanned at priority class 3, with at most `fill.max_jobs` uncached renders, and no Render event.
   - A pass that queued renders is followed by another pass, because a refresh may have replaced the queue. A pass is "done" per changedtick.
   - A new text restarts a running pass.
   - Fill is disabled in the bench's cold, scroll and warm-up rows, so those stay comparable with v1.
7. **"attach (sync)"** means the synchronous return of the deferred attach. The deferred first refresh is reported in its own row.
8. **Test changes:**
   - Tests that expect placements immediately call `core.attach(b, { sync = true })` (the plan's sync option).
   - M10 types its `:setlocal` with feedkeys (the new conceal rule).
   - Two test_term tests call `kitty.forget()`/`tmux.forget()` (memoization).
   - test_pool's "attach pre-starts a worker" became "warm open spawns no worker; InsertEnter warms one" and "first miss spawns", with stubs restored on failure.
   - The completion list includes `status`.
9. **"warm open spawns no worker":** tested with a buffer that has no formulas, not with a prefilled cache (it shows the same path: no job means no spawn).
10. **`status.collect()` formulas** come from `api.get_formulas` (full-equivalence detect). `cache.files/bytes` stay nil until the async walk.
11. **`env.lua`** (beyond the plan) holds the attach environment checks and `rearm()`, to keep core ≤ 700.

## Concerns

- **Upstream plugins were not executed.** The sandbox refused to run code from the upstream clones. I verified the interop paths by reading the upstream source (file references are in interop.lua comments), and the tests use fakes that mirror those layouts.
- **The deferred first refresh is still one main-thread block:** tex 5000 10 ms, md 2000 16 ms, right after open. In markdown it includes the `$$`-pair scan of the whole tree (about 2 ms) and the bounded detect.
- **Background fill is slow** for uncached documents: 4 renders per 50 ms idle slice, 27 s for 2068 formulas. It places every formula, so a big document keeps many resident images. They are pinned while placed, so max_images is exceeded.
- **Stale ids:** while rows are stale, duplicate formulas can be numbered differently (occurrence ids). A later detection can then clear and re-place an image (a cache hit). This is a brief flicker, not a wrong image.
- **"scroll 1 screen" max rose from 6 ms to 34 ms** (one sample; the median is unchanged). The likely causes are the bounded first detection (rows past the margin are stale until scrolled to) or lazy worker spawn. I did not investigate further.
- **Upstream assumption:** markdown keystroke speed depends on the highlighter's conceal_lines parse (decision 3). If that upstream behaviour changes, keystrokes go through the async/pending path. That path is also fast (about 1.3 ms), but placement waits for the parse.
- **Not done:** no manual check in a real Ghostty/kitty window (README manual items 15-19 were added). Every nvim run used NVIM_APPNAME=inkmath-dev, and ~/.config/nvim and the tmux config were not touched.
